# LED亮度检测上位机

## 模式切换与光源波形监测

顶部模式选择提供 **亮度检测** 和 **光源波形**。原有亮度检测仍使用
`A5 5A / 5A A5` 协议和 `lux` 单位，原有轮询、历史及保存行为保留。
光源波形使用荧光仪器的 `AA 00 01 / AA 01 00` 协议，两个模式在同一时刻
只允许一个串口采集线程运行；采集或连续记录过程中不能切换模式。

### 光源波形使用步骤

1. 在顶部切换到 **光源波形**，选择新组件的 COM 口。
2. 打开 **设置 → 波形设置**，设置通道、采样周期和单次点数，然后保存。
   默认通道1（目标0）、15ms/点、206点，预计采集时长3.09秒。
   通道可选1或2，周期和点数的协议范围均为1到65535；硬件支持范围以板卡为准。
3. 点击 **开始采集**。程序开灯并等待 ACK，然后仅发送一次采集命令。
4. 接收到指定点数和结束帧后自动关灯、释放串口。不会自动重复采集。
   中途可点击 **停止采集**；关闭窗口也会请求停止和关灯。
5. 点击 **保存本次**，将本次全部已收到的有效点保存为独立 Excel：
   `data/waveforms/YYYY_MM_DD/通道N_HHMMSS_微秒.xlsx`。文件不覆盖旧记录。
   中断或失败后也可保存已经接收到的点；下一次开始会重置内存曲线。

光源波形启动程序时不会自动开灯。它不使用亮度检测的连续记录、轮询间隔、
历史点数限制或保存抽样间隔；一批最多65535点。波形设置与原有亮度设置分别保留。

光源波形与亮度检测共用曲线面板：透明背景、坐标颜色、阶梯线和网格样式一致，
曲线设置中的线宽、网格和Y轴缩放对两个模式生效。波形横轴仍为采样相对时间，
纵轴仍为原始信号，不使用 lux 单位。
在 **设置 → 串口设置 → 显示串口原始返回** 开启后，两个模式都使用同一原始
返回面板，显示最近接收数据的时间、状态、完整字节数和HEX。不同完整返回帧
之间固定换行；单条返回仅在当前面板宽度不够时自动折行，窗口缩放时重新排版。
波形模式按解析器确认的帧边界分行，拆包时带上尚未完成的帧前缀，未解析字节
也保留显示，不会因为采样值里包含AA就将一条返回错误切开。
关闭开关恢复曲线。波形的原始返回不再使用底部日志，也不截断为160字节。

两个模式的顶部错误状态使用同一格式：`状态：通道 N 读取失败：原因 x 次数`，
并共用 **显示串口错误提示** 开关。波形停止后的错误汇总不会重复增加次数。
串口打开失败或无回包超时时，原始返回面板同样显示错误状态、字节长度及
`无返回`；部分返回仍保留已有字节。关闭顶部错误提示后，波形结束仍会显示
采集是否完成、关灯是否确认，避免将未确认的光源状态显示为已关灯。

### 波形通信和数据含义

- 串口：115200、8N1。
- 开灯/关灯：`AA 00 01 30 CH 00 01/00 CC 33 C3 3C`。
- 采集：`AA 00 01 50 CH 周期高 周期低 点数高 点数低 CC 33 C3 3C`。
- 数据：`AA 01 00 40 CH 序号高 序号低 原始值高 原始值低 CC 33 C3 3C`。
- 结束：11字节的 `0x40` 或 `0x50` 响应，状态字段为 `00 01`。
- `CH=0` 表示通道1，`CH=1` 表示通道2；参数使用大端无符号16位整数。

纵轴是 `原始无符号值 - 32768`，没有进行 lux、电压或浓度标定，也不进行
滤波、平滑或峰值分析。横轴由本批第一点开始，按照序号差乘设置周期推算。
Excel同时保留原始值、转换后信号、采样相对时间和电脑接收时间；接收时间
不等于真实采样时间。板卡可能集中返回，因此界面随实际回包更新。

解析支持拆包、粘包、完整帧尾校验和与安卓一致的完整载荷截断帧尾恢复；
恢复仅在下一帧响应头出现且前一帧载荷完整时执行，并记录日志。
重复/跳号、少点、超时或关灯未确认会明确提示，不会显示为完整采集成功。
所有已打开串口的退出路径都会尝试关灯；如果串口被拔出或硬件没有回应，
软件无法保证实际已关灯，需要检查设备。原始返回面板保留最近接收的一组响应，
不将收发日志混入采样数据。

## 功能概览

- 串口通信：`115200, 8N1`
- 通道范围：`1-16`
- 每个通道显示 16 路数据，界面为 4x4 卡片
- 后台持续轮询全部通道，切换通道时显示最近一次成功采集值
- 点击任一路 LED 卡片后，右侧显示该路历史曲线
- 支持显示当前通道最近一次串口 RX 原始 HEX，便于排查硬件和解析问题
- 支持普通保存：导出最近一段历史数据到 Excel
- 支持连续记录：长时间写入临时 CSV，停止后生成 Excel
- 支持设置串口超时、通道间隔、曲线显示、保存间隔、历史点数等参数
- 启动时检查 `requirements.txt` 依赖，缺失时提示并支持自动安装

## 串口使用

1. 插入硬件设备。
2. 启动程序。
3. 点击左上角 `选择COM口`。
4. 选择设备串口，例如 `COM5`。
5. 点击 `连接`。
6. 程序会按 `1-16` 通道循环读取。

读取失败或解析失败时，程序会在状态栏显示错误；该通道界面会继续保留上一次成功采集值，不会自动清零。

## 串口协议

读取命令：

```text
A5 5A XX 02 02 00 00 SUM
```

返回帧：

```text
5A A5 XX 02 40 + 16 个大端 IEEE754 float 光照强度值 + SUM
```

字段说明：

- `XX`：通道号，范围 `0x01` 到 `0x10`
- `02`：功能码
- `40`：payload 长度，十进制 64 字节
- `SUM`：从帧头开始逐字节累加后取低 8 位
- payload：16 个大端 IEEE754 float，单位按 `lux` 显示和导出

当前解析会校验帧头、通道号、功能码、长度和 SUM。只有校验通过的数据才会进入界面、历史曲线和保存链路。

## 数据保存

### 普通保存

关闭连续记录模式时，点击 `保存` 会导出最近一段历史数据。默认路径：

```text
data\YYYY_MM_DD\通道1\光照强度1.xlsx
data\YYYY_MM_DD\通道1\光照强度2.xlsx
...
data\YYYY_MM_DD\通道16\光照强度16.xlsx
```

Excel 第一列为真实采样时间，格式为 `HH:MM:SS.mmm`；第二列为 `光照强度(lux)` 文本。

### 连续记录

连续记录模式在 `设置` -> `高级设置` 中开启。开启后：

- `保存` 按钮用于开始记录
- 记录过程中按钮显示为 `停止`
- 点击 `停止` 后生成 Excel 文件
- 保存时长设置不生效，程序会从开始记录一直保存到手动停止
- 临时 CSV 保存在 `_temp_csv` 目录中，停止后转换为 Excel

保存目录按开始记录时间生成：

```text
data\YYYY_MM_DD\record_HHMMSS\通道1\光照强度1.xlsx
data\YYYY_MM_DD\record_HHMMSS\通道1\光照强度2.xlsx
...
data\YYYY_MM_DD\record_HHMMSS\通道16\光照强度16.xlsx
```

如果同一秒内重新开始连续记录，会复用同名 `record_HHMMSS` 目录并覆盖上一轮记录。

## 设置说明

- `READ_TIMEOUT_SECONDS`：串口读写最大等待时间，过小容易超时，过大会让异常响应变慢
- `ROUND_DELAY_SECONDS`：完成 16 通道一轮读取后的暂停时间
- `CHANNEL_DELAY_SECONDS`：每个通道读取完成后的等待时间
- `CURVE_VISIBLE_SECONDS`：曲线可见时间窗口
- `DEFAULT_MAX_POINTS`：每路历史缓存最大点数
- `DISPLAY_DECIMALS`：卡片显示小数位数
- `SHOW_SERIAL_ERRORS`：是否在状态栏显示串口读取失败
- `SHOW_RAW_SERIAL_VIEW`：是否在右侧显示原始串口返回
- `CONTINUOUS_RECORDING`：是否启用连续记录模式

串口超时和轮询间隔在下一次连接串口时生效；曲线和显示相关设置保存后会立即应用。

## 当前注意事项

- 显示、曲线和 Excel 导出统一使用 `光照强度(lux)`。
- 如果某通道读取失败，界面会保留该通道上一次成功采集值，不能直接理解为当前硬件实时值。
- `SUM` 校验较弱，不等同 CRC。遇到偶发异常值时，建议开启 `显示串口原始返回`，保留当次原始帧再判断是硬件返回、串口链路还是解析问题。
- 当前没有异常值过滤、跳变过滤或无光基线判断，所有通过协议校验的 float 都会进入显示和保存链路。
